## Decisions

1. §8a hoisted contract: `hooks/useIngredientEntry.ts`, composed with the commit, authored-food and candidate controllers by `hooks/useIngredientRowEditor.ts`, which the three hosts call (not by RecipeIngredientsFields: the Wizard renders only the current step, Wizard.tsx:285). Owns the text per target (a Map), ONE active target, ONE debounce, query and analytics session; the session settles when the active target changes or its row is removed. Target: `LineCommitTarget` (lineCommit.ts). Emits an `IngredientPick` into a new `useLineCommit` (admission leaves the search hook; `commitRouteFor` picks the route first). §4b: `validateRecipeForm(values, pendingEntryText)` takes the pending text as a required parameter. Combobox props: `ui/src/combobox/props.ts` plus `onFocus` (makes that row the active target), plus what `docs/design/rowEditorOpenDecisions.md`'s system changes 1 to 4 add: options with a detail line and their own accessible name (V3-5 removed the tag); a status line after the list; `Cancel` and a native clear button; a polite and an assertive channel.
2. §8b destinations — FIVE orphaned surfaces: disambiguation → row 6's candidates panel via per-row `useCandidateResolution` settling by line key (an UNRESOLVED admission is committed as is; whether the panel opens by itself is UX); `addFreeform` → the existing `declared` pick, draft route only (placement UX); authored-food form host → `useAuthoredFoodCreate` extracted, form moved into `form/` on `@commise/ui/sheet`, emits an `admitted` pick (Sheet or inline is UX); U29 live search → stays in the controller (the S5 seam), never triggered by typing (trigger placement UX); FIFTH: the correction control "Always use this for '{query}'" (IngredientPicker.tsx:209-266) is a control nested in an option (ARIA makes option children presentational) → a separate Command hosted after the pick with the typed phrase (placement UX; survival is the OWNER's). AMBIGUOUS: row 7's shortlist binds that one line (owner ruling 2026-10-02: no sibling binding), never through the combobox.
3. B6 gate (web): downshift 9.4.0 `useCombobox` + `@floating-ui/react-dom` 2.1.9 (flip, size, autoUpdate). Hand-rolled rejected: no scroll-into-view for the active option, no IME guard on Enter. Spec gaps closed by extension points: Home/End (host onKeyDown sets preventDownshiftDefault); Escape on a closed list reaches the host, which cancels Change food (`rowEditorOpenDecisions.md` system change 8; this replaces "the stateReducer keeps the text"); blur/Tab selects the highlighted option (reducer keeps the selection); highlight is a bare index that survives an items change (control highlightedIndex from an active key via onHighlightedIndexChange); a busy option refused in the reducer, not isItemDisabled; Enter on a closed list: host preventDefault. floating-ui 2.1.9 already in the lockfile via @radix-ui/react-popper. Rejected: Radix Popover as list host (role dialog + focus scope + its own dismissal), React Aria, Ariakit (pre-1.0), cmdk. Native: no library; house TextInput, Pressable options, LiveRegion, an `open` boolean; `comboboxNavigation.ts` deleted. The native list is in flow below the field (`rowEditorOpenDecisions.md` item 7).
4. hasVariants (built 2026-10-02; present only on a `found` ROOT entry whose food stated it, `true` meaning a live variant exists; absent on every variant ref, on an authored food and whenever not known; a stale entry carries the cached value): recipe's `POST /ingredients/food-nutrition` `found` entry for a root ref gains optional `hasVariants` from food's `hasLiveVariants` (gateway already reads it, foodNutrition.gateway.ts:290). `LookupEntry` carries it; the row policy reads it; NOT copied into the draft (values.ts:121). Additive wire; recipe hash moves; regenerate packages/schemas/recipe. If UX puts Add details on row 8, `refsOf` also asks for withheld lines' refs and gates their figures in the consumer.
5. Sheet: `onDismissed?: () => void`, called once off screen after a close by any route. RN 0.86 fires `onDismiss` on iOS only and only for a Modal kept mounted with visible={false} (Modal.js:240-283, 318-327), so Sheet.native stops returning null when closed. Android and web: from an effect when open goes false. Both ActionMenu leaves hold the chosen item and run it after dismissal. On web the trigger (`⋮`) takes focus before the held item runs, so a dialog the item opens records `⋮` as its return target. On native, focus returns to the trigger only when no item was chosen.
6. Layering: `variantPartTexts` → `detail/lineName.ts` (pure). `isCatalogWithheld` and `hasCatalogNutrition` → recipe-core `nutrition.ts` (ingredientSpecialization.md:1149).
7. Commit port by surface (IngredientPick gains `catalogVariant`; Remove details is a `catalogFood` pick of the root). The read view has no row action (§S5 of `ingredientSpecialization.md`), so it has no commit port. Edit form, stored line → the same command via `commitRouteFor` (ADR-0045; curated U14's "form value on the edit form" is wrong for stored lines). Edit form new line and create form → `by-food-variant` then the `rebindIngredient` draft action (wire sends only ingredientId, wire.ts:53, so U14's "no network call" is false). Import review: no host (a parse binds nothing). Command adapter: runs after any save/autosave in flight; sends expectedVersion = baseVersion; on success adopts the answered version (unchanged for a no-op), re-points the persisted snapshot onto the EXISTING keys by stored position (never re-run seedLineKey), applies withLineBinding to that key; a 409 goes to the editor's conflict state. The recipe page's ambiguity review commits each pick through the same rebind command, for that one line only (owner ruling 2026-10-02).
