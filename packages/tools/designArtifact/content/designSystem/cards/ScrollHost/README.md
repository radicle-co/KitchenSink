ScrollHost is the one provider per screen over the screen's one vertical scroller, and it reports what the chrome reacts to. It exposes `condensed` (the large title has scrolled away), `scrollingDown`, `atTop`, `current` section, and depth in viewports, and it moves the scroller with `scrollToTop`, `scrollToSection`, `scrollToField` and `revealSpan`. Props are `headingId`, an ordered `sections` id list and `activationOffset` below a sticky bar. On web the document scrolls and the host finds the heading and sections by element id, so they need ids and `tabIndex={-1}`; jumps move focus, record the hash and are instant under reduced motion. Consumers only read it through `useScrollHost()` (which throws without a host above), and nothing else should hold the scroller. On native the screen's scroller spreads `bind` onto itself, so a ScrollView, FlatList or FlashList all work, and the heading and each section report their layout as direct children of the content container.
