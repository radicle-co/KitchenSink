**Distinct-requester demand (canonical).** Enqueue upserts `(food_id, sub)` into `fetch_requesters`
`ON CONFLICT (food_id, sub) DO NOTHING`, then sets `fetch_queue.request_count` to the **capped distinct-`sub`
count (`PRIORITY_CAP = 1`)** — never a raw `+1`. Paired with `pg_notify('fetch_queued', food_id)`. (FR-044.)

**Auto-resolve boundary (canonical, D-AUTORESOLVE).** After pre-merge dedup, the worker counts candidates
surviving **normalized-name exact match**: exactly **1 → `RESOLVED`**; **>1 → `UNRESOLVED`**; **0 →
`NOT_FOUND`**. Bias toward `UNRESOLVED` over a wrong auto-pick (human is the final arbiter). **No nutrient
tolerance** (the `±10%`/`FOOD_AUTORESOLVE_NUTRIENT_TOLERANCE` knob is dropped).

## 2. Canonical data model

**Authority:** `plan.md §2` is canonical. The **only** structural additions allowed by stabilization are
(a) the `food_candidates` table, (b) the `leased_at` lease column, and (c) the provenance same-food FK
constraints. No other schema change.

**Table list (13).** The 12 tables already in `plan.md §2` "Final table list" —
`food`, `food_sources`, `nutrient`, `food_nutrients`, `food_portions`, `food_field_provenance`,
`food_category`, `food_category_assignment`, `fetch_queue`, `fetch_requesters`, `source_call_log`,
`source_sync_metadata` — **plus `food_candidates`** = **13**. (Removed-table set stays removed:
`foods`, `usda_sync_metadata`, `usda_call_log`, `rate_limiter_state`, `user_fetch_quota`,
`global_fetch_quota`, and all denormalized-nutrient / `raw_json` / `fetch_status` columns.)

**Addition A — `food_candidates` (D-CANDIDATES).** Backs `UNRESOLVED` / US-2a (`GET /candidates` →
`PATCH`-resolve). The worker persists surviving per-source candidates on an `UNRESOLVED` outcome;
`PATCH`-resolve reads/validates against and then clears this table.

```
food_candidates (
  id           text PRIMARY KEY,           -- ULID
  food_id      text NOT NULL REFERENCES food(id) ON DELETE CASCADE,
  source       food_source NOT NULL,
  external_key text NOT NULL,
  name         text NOT NULL,
  summary      text,
  created_at   timestamptz NOT NULL DEFAULT now(),
  UNIQUE (food_id, source, external_key)
)
```

**Addition B — worker lease (D-LEASE).** Add `leased_at timestamptz` to `fetch_queue`. A reaper reverts
`status='in_flight'` rows whose `leased_at < now() - 30s` back to `pending` (consumer start + every minute).
Single-drainer is enforced via the existing Postgres advisory lock (FR-022) — keep and cross-link; this
makes "zero 429 in any window" safe because the read-committed count+insert is effectively serial.

**Addition C — provenance same-food integrity (D-PROVENANCE-FK).** Add `UNIQUE(food_id, id)` to
`food_sources`; change the `source_id` references on `food_nutrients`, `food_portions`,
`food_field_provenance` (and `food_category_assignment`) to **composite `(food_id, source_id)` FKs** so a
value row can only reference a `food_sources` row of the **same** `food_id`. `ON DELETE` for these FKs is
**`NO ACTION`** — a DIRECT `food_sources`-row delete that would orphan a golden/manual value is still
blocked, but because `NO ACTION` defers its check to end-of-statement (unlike `RESTRICT`, which checks
immediately), a **food-level `ON DELETE CASCADE`** still succeeds: deleting a `food` row cascade-deletes
both the `food_sources` rows and the referencing value rows within the same statement. (`RESTRICT` would
abort that cascade nondeterministically, since Postgres does not order sibling cascade targets.) `food_id`
FKs to `food` remain `ON DELETE CASCADE` as today.

**Operational data is `fetch_requesters` + `source_call_log`** (no quota tables). `source_call_log` is the
rolling-window ledger; rows older than the trailing 60-min window are pruned on a periodic sweep (D §4
ADD: retention rule).

Everything else (internal ULID `id` identity; no source-native key as PK/FK; no raw payload; no EAV;
`pg_trgm` search; numeric/decimal nutrient amounts) is per `plan.md §2` and unchanged.
