# Research: Public Versions of Imported Recipes

Each item gives the decision, the reason, and the options set aside.

## R1. Engine ownership

- **Decision**: 027 owns the engine's design. 003B builds 027's core and adapter first. 003B owns the import side
  beyond that.
- **Reason**: 027 FR-045 already names the import-time rewrite as a consumer. Two engines drift on the facts
  sheet and the checks, and those are the rules that hold the feature up.
- **Set aside**: 003B owning the engine. That splits one design across two specs.

## R2. Where the job lives

- **Decision**: a `public_version_jobs` table of its own, keyed on the source record.
- **Reason**: the import item is purged on the schedule of ADR-0072, and the later route (US3) has no
  item at all. The job also holds the writer's source step text (`source_steps`) until it ends (cleared at most 73 h 15 min after Start while the sweep runs, FR-033), so a retry on the public-only path sends the same text. The item's draft
  (`recipe_import_items.payload`) follows FR-033: it clears only through `claimSave` (every save that ends the paste in a recipe, FR-016a), or goes with the import on an explicit discard, and otherwise ADR-0072's 30-day purge removes it.
  The sweep clears only the job's own text.
- **Set aside**: columns on the import item.

## R3. The comparator for every later save

- **Decision**: a keyed hash of each word 5-shingle of the source's steps, and of each 2-word shingle of its title,
  stored as `bigint[]` with a format version and a key version. The normalised source title is stored as one hash.
  The comparison form is the one defined in 027 research R3.
- **Reason**: the "For everyone" path keeps no text once the import ends (Publish, keepPrivate or an explicit discard, FR-033), but FR-050 must still run on every save. A hash set answers
  Jaccard and containment with no text.
- **Set aside**: keeping the pasted text after the import ends (the job's copy clears when the job ends, and the item's draft on Publish, keepPrivate or an explicit discard, or else at ADR-0072's 30-day purge, FR-033). Keeping only a digest (it cannot measure
  closeness).

## R4. Title

- **Decision**: built by code from the facts sheet: the two main foods by weight.
- **Reason**: 027 never changes a title, so a title field in the engine answer is a mode flag. A code title costs
  nothing and never echoes the source.
- **Set aside**: a title in the engine answer. A second prompt now. It stays the fallback for poor code titles in the bake-off.

## R5. Classification inputs

- **Decision**: one pure function reads the evidence, the statement, the live site claim and three data lists
  (honoured licences, federal publishers, paid sites). The paid-site list is 004-FR-014's existing list. Each list
  is data with an admin lifecycle (D-004 shape).
- **Reason**: an allowlist that fails closed. One reader for one rule.

## R6. Idempotent Publish

- **Decision**: one transaction, in the lock order of the data model (import header, item, allowance, DD33, then the job row). Insert the recipe under a unique source page key. Mark the job `published`. A second device gets the existing
  recipe id.

## R7. Spend

- **Decision**: call site `import-public-rewrite`, under the one verification role, operating cost, final
  `budgetSpent`. No per-cook cap: one version per source page and 3 attempts per holder (the import item, then the saved recipe) bound it, under the pool's ceiling.
- **Reason**: ADR-0024 §4c and §6, and the paste fallback's precedent (004-FR-059).
