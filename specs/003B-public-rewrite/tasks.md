## How to read this list

- **Test-first is law.** In every phase the failing tests come first, in every tier the change touches. Run them and
  watch them fail before the code they cover. A test task that has never failed is not done.
- **Tiers.** Non-UI code gets unit and integration (database mocked). The migration and the publish transaction get a
  LOCAL e2e on a real database. The service gets a service e2e and a k6 scenario (k6 runs by hand only). Every UI
  state gets a vitest component test. Unit tests are always written, and each behaviour is proved with the cheapest tier
  that proves it (unit, component, integration). During development an e2e test is written only when no lower tier
  can prove the behaviour. Every story in the MVP still gets its Playwright spec and its Maestro flow, written together in the
  one end-of-feature wrap-up task T402 and run once, at the final head of the PR. The feature is not done until it
  merges.
- **Run only impacted e2e.** Use `npm run e2e:plan -- --base origin/main` and the root doors (`test:e2e:web`,
  `test:e2e:mobile`). Never start `playwright test` or `maestro test` by hand.
- **Format**: `- [ ] Tnnn {slice} [P?] [Story?] Description with path`. The `{slice}` tag names the PR the task ships in: A1 to A7 (engine), A1b (Unicode tables, script check and skeleton fold), B1 to B5 (paste and link import), P0 to P10 (server), P3b (age assurance), P12 (input door), P11 (editor routes, after #322), D0 (docs and ADRs), C2a (paste screens, web), U0b, U1 to U5 and U7 (choice UI) and UC (the public-page credit, licence and report on the recipe detail, the recipe menu items, and the copy refusal UI; not 003A's unit U6), UW (the end-of-feature e2e wrap-up), L1 (seed and launch) and L2 (after launch). `done` marks work already in the tree. A range such as `U2-U5` is a train of PRs, and each task in it ships in the PR of the screen it builds. A test and the code that passes it ship in one PR even when their tags differ, and, when their tags differ, the code task names its tests in its "first" list. `[P]` means a different file with no open dependency.
- **Owner rulings that override the docs**: no Anthropic model anywhere (Bedrock non-Anthropic only); no facts cards;
  no caps of any kind; a link import fetches on the device first and the server second, and the server never fetches
  a known paid site (the cook is asked to paste); one public version per source page; one import allowance for every
  user-facing import; publishing needs age 16 or over.
- **Not in this list**: any edit to `packages/shared/page-reader`. Another agent owns it. Tasks that need it wait for it.
- **Built dependencies**: the evidence table `recipe_source_evidence` (migration 0086), statement attestations
  `recipe_statement_attestations` (migration 0088), ADR-0095, and "imports save private only" are on main. Tasks marked
  `(needs ...)` below name only what is still open.
- **Paths**: `RS` is `packages/services/recipe-service/src`, `RW` is `packages/services/recipe-workers/src`, `RC` is
  `packages/shared/recipe-core/src`, `FR` is `packages/apps/commise/features/recipes/src`. File names follow
  `docs/CODING_STANDARDS.md` §1.
