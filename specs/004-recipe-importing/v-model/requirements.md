## Overview

Recipe Importing lets users bring recipes into Commise from four channels — public website URLs, Instagram
posts, structured files, and photographs of physical copies. Every channel produces an **import draft** that
the user reviews and completes; confirming the draft creates the Recipe through 001's shipped write path.

The feature's scope is **ingestion**. The Recipe entity, attribution columns, clone behaviour, and the C-004
visibility policy are already shipped in 001 and are consumed here, not redefined (see `spec.md` →
_Relationship to shipped 001_).

## Assumptions

- Attribution is a display obligation; the system stores recipe metadata and does not rehost source imagery or
  full article prose.
- OCR accuracy on photographs — especially handwriting — is materially worse than structured-markup extraction.
  The draft-and-confirm model is what makes that acceptable; SC-002 explicitly excludes OCR.
- Ingredient-line parsing is heuristic and will mis-parse a minority of lines; retaining the raw line verbatim
  is what keeps a mis-parse recoverable rather than lossy.
- The paywalled-domain blocklist is necessarily incomplete and is maintained operationally (D-004).

## Dependencies

- **001-commise-recipe-app** — Required, and largely already shipped. Provides the Recipe entity, attribution
  columns, clone, the C-004 visibility policy, the error envelope, and rate limiting.
- **002-user-auth** — Required. Session-token authentication on every import endpoint.
- **003-usda-food-data** — Required. Asynchronous ingredient resolution via the typed food-service client.
- **010-subscriptions** — Referenced. Premium entitlement gates clone-to-private (`004-FR-011`).
- **External (non-blocking)** — an approved Meta application for `REQ-005` / `REQ-IF-001` (D-002).

## Glossary

| Term                 | Definition                                                                                                                                                |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Import Draft         | Owner-scoped, expiring staging record holding extracted content, per-field confidence, and missing-field list. Confirming it creates the Recipe.          |
| Import Channel       | How content arrived: `url`, `instagram`, `file`, `ocr`, `manual`. Distinct from `sourceType`, which is the policy classification.                         |
| Canonical Source URL | The normalized dedup key — scheme and host lowercased, default port and fragment removed, tracking parameters stripped, trailing slash normalized.        |
| Provenance           | The classification (`imported_public` / `imported_physical` / `imported_paid`) that drives the shipped C-004 visibility policy.                           |
| Substantive Edit     | A change to ingredients or steps — 001's shipped threshold permitting a premium user to make a clone private. Title/description/tag changes do not count. |
| Structured Markup    | Machine-readable recipe data embedded in a page: schema.org JSON-LD (preferred) or microdata.                                                             |
| Attestation          | The user's explicit declaration of a manually entered recipe's origin, with a citation (D-003).                                                           |
